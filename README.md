# f4ge-supplier-risk

협력사 품질 리스크 예측. **오더 1건**이 최종적으로 어떤 품질로 끝날지를,
**공장이 데이터를 거의 주지 않는 조건에서** 예측한다.

## 왜 기존 `f4ge-quality-prediction` 과 다른가

| | 품질예측 | 이 리포 |
| --- | --- | --- |
| 단위 | lot | **오더** |
| 사용자 | 공장 관리자 | **F4GE (발주자)** |
| 라벨 | 없다 | **우리가 갖고 있다** |
| y | `is_defect` 이진 | **Beta-Binomial** (AQL 표본 k/n) |
| 불량률 스케일 | 내부 불량 5~25% | **escape 0.05~0.5%** |

승계하는 것: 계약 규율(ID 패턴 · ISO-8601 · 멀티테넌트) · calibration 게이트 ·
시간순 분할과 누수 원칙 · 체크포인트(진행률별 모델) · 대시보드 골격.

생성기 · 모델 · 채점 · 운영 서버 · 화면까지 동작한다. 테스트 57건 통과.

## 무엇이 얼마나 맞는가

8 seed · 공장 12곳 · 오더 330건(36개월, 1공장 1오더) · 시간순 테스트 100건.
순위상관은 생성기 진실값과의 Spearman.

| 목표 | 계산처 | ρ | ±sd |
| --- | --- | --- | --- |
| 유출률 (escape) | `two_stage` | **+0.823** | 0.054 |
| 제조 품질 — 오더 내부 불량률 p | 분해식 `factory_params` | **+0.920** | 0.023 |
| 제조 품질 — 같은 값 | `hier_bayes` multi-head | **+0.953** | 0.015 |
| 검수 품질 — 검출률 d (12곳) | `two_stage` | **+0.531** | 0.213 |

유출 예측은 `two_stage` 가 8 seed 전부 1위다. HistGradientBoosting +0.460 ·
MLP +0.409 · ensemble +0.699 로 라벨 330건에서는 tree 와 신경망이 못 미치고 분산이 크다.

검출률 d 가 낮은 것은 추정 절차 탓이 아니다. SBC 120 시뮬레이션에서 `hier_bayes` 의
mu · tau · log_kappa rank 가 전부 uniform 이다(χ² p 0.140 / 0.150 / 0.439). 원인은 표본이다 —
12곳 검출률이 0.957~0.99 로 좁고, 진짜 잡은 불량 수를 오라클로 줘도 ρ 0.42 에 머문다.

## 화면과 권고

- 화면은 `/` 하나다(`web/static/공장관제.html`).
- 카드 KPI 는 **「품질 리스크 %」 하나**다. 이 오더의 ISO 2859-1 수준 II 표본에서
  불량이 1개 이상 나올 확률, `1 − (1 − 유출률)^n`. 결과가 도착하면 맞았는지 확인된다.
- 권고는 `review_needed` 하나. 예측 유출률 상위 10% 로 자른다 →
  100건 중 **9.6건**, 정밀도 **92.2%**(기저 20.2%, 4.6배).

## 쓰는 법

```bash
pip install -e ".[dev]"

sr generate                     # 합성 데이터 생성 → datasets/generated
sr calibrate                    # 검증 게이트
sr score                        # 채점 → supplier-risk-score.v1

sr seed --score                 # 계약 경로로 DB 에 넣고 admin 키 발급 + 채점 1회 (데모)
sr serve --port 8020            # 서버 → http://localhost:8020/?key=<키>
sr key --role site --factory fac_kr_01 --label "공장01 현장"
sr score-run                    # cron 용. MES 가 일 1회라 일 배치로 충분하다
```

DB 는 `SR_DATABASE_URL` 로 바꾼다(기본 `sqlite:///data/supplier_risk.db`).
API key 는 세 역할이다 — `admin` 전 공장 · `site` 자기 공장 하나 · `ingest` 쓰기만.
키는 해시만 저장한다.

## 전제 (2026-09-11 기준)

- FactoryOS 소스 4개(MES · CellOS · ERP · 포지 기록)가 12곳 전부에서 온다. 공장 유형 구분은 폐기했다.
- **공장 차이는 물리적인 것만**이다 — 무엇을 만드는가 · 제조 능력 · 검출 능력 · 공정 드리프트.
  보고 편향 · 노이즈 · 성실도는 생성기에서 통제했다(값은 `configs/generator.yaml` 주석).
- 한 공장은 한 번에 한 오더. 330건 / 36개월.
- 목표는 둘이다 — **제조 품질**(내부 불량률 p) · **검수 품질**(검출률 d).
  `models/factory_params.py` 가 ERP · Cell 물리 폐기 + MES 보고 + 입고검사로 분해한다.
  분해는 `s`(잡은 불량 중 폐기 비중) 가정값 0.115 하나에 눈금이 달려 있다.

## 규칙

- **모델을 더 붙이지 않는다.** 유출 순위는 후보 셋과 multi-head 가 0.824 로 동률이다.
  병목은 모델이 아니라 표본이다.
- **검출률 추세는 표본 ×2 이후에 주장한다.** 지금 d 의 최소 seed 는 0.007 이다.
  검사율을 8% → 15% 로 올리면 0.566 이 되고, 그때 「검출률」을 처음 주장할 수 있다.
  비용은 검사원 +0.3명 · 월 89만원(내부 인건비 22,000원/h 가정) · 입고 지연 +0.5일.
- 화폐 환산 표의 세 가정(유닛당 검사 3분 · 인건비 22,000원/h · 외주 50,000원/h)은
  실제 값으로 바꾸면 표가 다시 나온다. `docs/_표본설계_화폐환산.md` 머리말 참조.
