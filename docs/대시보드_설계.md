## 0. 디자인 시스템은 승계한다

**기존 `f4ge-quality-prediction` 의 운영자 대시보드에서 그대로 가져왔다** —
`src/f4ge_quality_prediction/web/static/dashboard.html`. 토큰 이름·값과 컴포넌트 규칙을
바꾸지 않는다. 두 제품이 같은 화면 문법을 쓰면 나중에 한 화면에 붙일 때 이음매가 없다.

| 승계한 것 | |
| --- | --- |
| 색 토큰 | `--page` `--card` `--border` `--divider` `--text` `--text-2` `--label` `--muted` `--placeholder` `--track` `--fill` |
| 위험 4-tier | `--risk-{low,medium,high,critical}-{bg,br,tx}` — 배경 + inset 링 + 글자색 3종 세트 |
| 이상 밴드 | `--anomaly-band` `--anomaly-edge` |
| 타이포 | Inter / Menlo · 본문 `400 13px/20px` |
| 컴포넌트 | 56px sticky 헤더 + `.tabs` · `.card`/`.card-head`/`.card-title` · `.chip` 계열 · `.bar > i` · 표 규칙 |

다크 모드는 원본 값을 그대로 쓰되 **`[data-theme]` 스탬프까지 받도록 확장**했다.
원본은 OS 설정만 따랐는데, 아티팩트는 뷰어의 명시적 테마 선택이 이겨야 한다.

### ★ 승계한 것 중 제일 중요한 것 — 색 채널을 섞지 않는다

원본 주석이 이렇게 말한다.

> 설비 상태 = 무채색 전용 채널. 위험 4-tier 색과 절대 섞지 않는다:
> **alarm(설비 정지)과 critical(품질 위험)은 둘 다 빨간 상황이지만 뜻이 정반대다.**

이 프로젝트에서는 **불일치와 품질 위험**이 정확히 그 관계다. 그래서 채널을 셋으로 나눈다.

| 채널 | 무엇 | 표현 |
| --- | --- | --- |
| **위험 4-tier** | 이 오더가 불량으로 끝날 것 같은가 | `.chip.risk.*` — 컬러 |
| **권고** | 검토가 필요한가 | `.chip.act` — **무채색**. `검토 필요` 는 `fill` 반전 |
| **불일치** | 보고를 믿을 수 있는가 | `.chip.gap` — **이상 밴드 색**. 위험 팔레트를 빌리지 않는다 |

불일치가 높은 것과 품질 위험이 높은 것을 같은 빨강으로 칠하면,
정반대 대응이 필요한 두 상황이 한 색으로 보인다.

## 1. 왜 두 화면이 다른가

같은 데이터를 쓰지만 **보여주는 것이 다르다.** 그리고 그 차이가 설계의 핵심이다.

| | 관리자 (F4GE) | 현장 (공장) |
| --- | --- | --- |
| 범위 | 전 공장 | **자기 공장만** |
| 예측 품질 | ○ | ○ |
| 보고 품질 | ○ | ○ (자기 것) |
| **불일치도** | ○ | **✕** |
| **공장 순위·비교** | ○ | **✕** |
| 개선 항목 | — | ○ |

### 현장에 불일치도를 보여주지 않는 이유

무엇을 재는지 알려주면 **그 지표부터 맞춰 온다.** Goodhart 문헌의 표현대로
"측정 대상이 자기 데이터를 보고하면 독립 검증 없이는 지표가 부풀려진다"
(`유사제품_조사.md` §5).

불일치도는 자기신고와 증거의 잔차다. 어느 증거를 쓰는지 알려주는 순간
그 증거까지 맞춰 오기 시작하고, 지표가 죽는다.

**대신 현장에는 행동으로 옮길 수 있는 것만 보여준다** — FAI 제출률, 보고 누락,
보고 지연, 자체검사 기입률. 전부 **품질과 별개로 기록만 바꿔도 평가가 달라지는 항목**이다.
이건 감추는 것이 아니라 **개선 경로를 주는 것**이고, 실제로 그렇게 작동한다:
기록이 채워지면 예측이 과거 실적 쪽으로 덜 기울고 그만큼 덜 보수적으로 평가된다.

> ⚠ 점수를 어느 수준까지 공개할지는 **경영 판단**이다(CTO 질문 15번).
> 여기 잡은 것은 기본값이고, 순위 공개는 관계 리스크라 기술 판단으로 정할 사안이 아니다.

## 2. 관리자 화면

### 액션 큐 (상단)

`검토 필요` · `해당 없음` — **진행 중 오더 기준**. (09-08 저녁: 세 갈래 권고를 `검토 필요` 하나로 합쳤다 — §7.)
완료된 오더의 권고는 큐에 넣지 않는다. 지금 할 수 있는 것만 센다.

### 진행 중 오더 표

권고 우선순위 → 예상 불량 순으로 정렬. 한 줄에 **세 값이 다 보인다** —
`예상 불량(PPM)` · `공장 보고` · `불일치`. 셋을 나란히 놓아야 판단이 선다.

### ★ 공장 매트릭스 — 이 화면의 중심

```
        보고를 못 믿음
              │
   보고 검토   │   보고 + 품질 검토
              │
──────────────┼────────────── 예상 불량 (PPM, 로그) →
              │
  검토 대상 아님│   품질 검토
              │
        보고가 일관됨
```

**가로축은 품질, 세로축은 신뢰.** 두 축이 서로 다른 질문에 답하고 사분면마다 검토할 것이 다르다.
오른쪽 아래(정직한데 품질이 나쁨)는 품질을, 왼쪽 위(숫자는 좋은데 못 믿음)는 보고를
검토한다 — **숫자가 좋아 보이는 것 자체가 신호**이기 때문이다.

실측(`불일치탐지.md` §4-1, §9): 권고를 `검토 필요` 하나로 합친 뒤 전체 오더의 검토 필요는
실제로 나쁜 오더를 46.2% 잡는다(기저 20.0%). 보고 있는 오더의 검토 필요가 편향 심한 공장을 잡는 정밀도는
39.0% 로 기저 39.9% 와 같다 — 합치기 전 축별 값(77.2% · 37.5%)은 §9 참조.

신뢰도 하위 25% 공장은 **점선 테두리 + 라벨**로 표시한다. 색만으로 구분하지 않는다.

### 공장 상세 — 공장을 누르면 열린다

공장별 실적 표의 행이나 매트릭스의 점을 누르면 그 공장 화면으로 들어간다.

**중심은 「이 숫자가 어떻게 나오는가」 카드다.** 2단 모델의 두 단계를 그대로 화면에 편다.

```
① 공장이 보고한 내부 불량률   ×   ② 보정 계수 κ   =   예상 유출 불량
        0.63%                      0.0523              326 PPM
   전수에 가까운 관측                우리 입고검사        고객에게 도달하는 값
   정보량은 크지만 편향             3건으로 추정
```

κ 는 `(1 − 검사 검출률) ÷ 보고 편향` 이다. 두 값을 따로 알 필요 없이 **비만 알면 된다**.
막대에 전체 평균을 함께 찍어 "이 공장을 평균의 몇 배로 보정하는가"를 보여주고,
**관측 건수를 같이 적는다** — 우리 라벨은 희소해서 3건짜리 추정과 30건짜리 추정은
신뢰도가 다르고, 화면이 그 사실을 숨기면 안 된다.

나머지 넷:

| | |
| --- | --- |
| **오더별 예상 불량** | 시간순 · 로그 축 · 위험 등급 색. 속 빈 점 = 진행 중 |
| **예측 vs 실제** | 예측 구간별 실제 로트 불합격과 표본 실측. ⚠ 표본 불량은 대부분 0이라 **오더 몇 건으로는 판정할 수 없다**는 것을 캡션이 말한다 |
| **보고 신뢰도 이력** | 오더별 불일치 막대. 위 = 증거보다 좋게 보고. threshold 초과는 이상 밴드 색 |
| **오더 전체** | 진행/완료 · 예측 · 보고 · 불일치 · FAI · 실제 결과 · 권고 |

> KPI 는 **화면에 보이는 오더(채점 구간)로 통일한다.** 처음엔 전체 이력 불합격률과
> 채점 구간 표본 실측을 나란히 놨더니 "2.7% 인데 0건 발견" 같은 모순된 두 숫자가
> 한 줄에 앉았다. 모집단이 다른 값을 나란히 놓으면 안 된다.

## 3-1. 브라우저로 확인하며 고친 것

화면은 **열어 보기 전까지 맞는지 알 수 없다.** 25개 상태(관리자 · 공장 상세 12 · 현장 12)를
순회하며 잡은 것들.

| 증상 | 원인 | 조치 |
| --- | --- | --- |
| 진척 바의 트랙이 아예 안 그려짐 | `.bar` 가 `<span>` = `display:inline`. **인라인엔 `min-width` 가 안 먹는다** | `inline-block` + 고정 폭 |
| 매트릭스 라벨이 다른 공장 점과 사분면 캡션을 가림 | 라벨끼리만 피하고 점·캡션은 장애물이 아니었다 | 점·캡션을 장애물로 등록. **자기 점은 제외** (안 하면 모든 라벨이 아래로 밀린다) |
| 추이 차트 축 눈금이 안 보임 | 눈금이 `[100,1000,10000]` 고정이라 데이터 범위 밖 | 데이터에서 `1·2·5 × 10ⁿ` 로 유도 |
| KPI 에 "2.7% 인데 0건 발견" | 전체 이력 비율과 채점 구간 실측을 나란히 놨다 | **화면에 보이는 오더로 통일** |
| 900px 에서 `권고` 열이 잘림 | 열 순서가 오더→…→권고 였다 | **권고를 세 번째로.** 부수 열(수량·납품처)은 1180px 미만에서 접는다 |
| **「위험 높음」인데 「권고 없음」** 행 | `high` 컷(상위 20%)과 예측 위험 쪽 검토 컷(상위 10%)이 다른 선이었다 | `_RISK_Q` 를 `(0.60, 0.90, 0.97)` 로 바꿔 **같은 선에 맞춤** → 모순 행 0건 |

마지막 것은 **화면 버그가 아니라 모델 설정 오류**였다. 등급과 권고가 다른 분위수를 쓰면
"위험 높음 · 권고 없음" 조합이 표에 그대로 출력된다. 화면이 아니라 `_RISK_Q` 를 고쳤다.

> 가로 스크롤은 되지만 **스크롤해야 보이는 열은 사실상 없는 열**이고,
> 판단에 쓰는 열이 화면 밖에 있으면 표가 그 판단을 지원하지 못한다.

## 4. 표시 규칙

- **PPM 단위로 낸다.** 구매·품질 담당자가 쓰는 문법이라 설명이 필요 없다

- 위험 등급은 계약의 4-tier(`low`/`medium`/`high`/`critical`)를 그대로 쓴다
