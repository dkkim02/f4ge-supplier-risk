## 1. 왜 두 화면이 다른가

같은 데이터를 쓰지만 **보여주는 것이 다르다.** 그리고 그 차이가 설계의 핵심이다.

| | 관리자 (F4GE) | 현장 (공장) |
| --- | --- | --- |
| 범위 | 전 공장 | **자기 공장만** |
| 예측 품질 | ○ | ○ |
| 보고 품질 | ○ | ○ (자기 것) |
| **불일치도** | ○ | **✕** |
| **공장 순위·비교** | ○ | **✕** |
| 개선 항목 | — | ○ |

### 현장에 불일치도를 보여주지 않는 이유

무엇을 재는지 알려주면 **그 지표부터 맞춰 온다.** Goodhart 문헌의 표현대로
"측정 대상이 자기 데이터를 보고하면 독립 검증 없이는 지표가 부풀려진다"
(`유사제품_조사.md` §5).

불일치도는 자기신고와 증거의 잔차다. 어느 증거를 쓰는지 알려주는 순간
그 증거까지 맞춰 오기 시작하고, 지표가 죽는다.

**대신 현장에는 행동으로 옮길 수 있는 것만 보여준다** — FAI 제출률, 보고 누락,
보고 지연, 자체검사 기입률. 전부 **품질과 별개로 기록만 바꿔도 평가가 달라지는 항목**이다.
이건 감추는 것이 아니라 **개선 경로를 주는 것**이고, 실제로 그렇게 작동한다:
기록이 채워지면 예측이 과거 실적 쪽으로 덜 기울고 그만큼 덜 보수적으로 평가된다.

> ⚠ 점수를 어느 수준까지 공개할지는 **경영 판단**이다(CTO 질문 15번).
> 여기 잡은 것은 기본값이고, 순위 공개는 관계 리스크라 기술 판단으로 정할 사안이 아니다.

## 2. 관리자 화면

### 액션 큐 (상단)

`현장 방문` · `검사 강화` · `전화` · `조치 없음` — **진행 중 오더 기준**.
완료된 오더의 권고는 큐에 넣지 않는다. 지금 할 수 있는 것만 센다.

### 진행 중 오더 표

권고 우선순위 → 예상 불량 순으로 정렬. 한 줄에 **세 값이 다 보인다** —
`예상 불량(PPM)` · `공장 보고` · `불일치`. 셋을 나란히 놓아야 판단이 선다.

### ★ 공장 매트릭스 — 이 화면의 중심

```
        보고를 못 믿음
              │
   가서 본다   │   가서 본다 + 검사 조인다
              │
──────────────┼────────────── 예상 불량 (PPM, 로그) →
              │
   그대로 둔다 │   검사를 조인다
              │
        보고가 일관됨
```

**가로축은 품질, 세로축은 신뢰.** 두 축이 서로 다른 질문에 답하고 사분면마다 대응이 다르다.
오른쪽 아래(정직한데 품질이 나쁨)는 검사를 조이면 되고, 왼쪽 위(숫자는 좋은데 못 믿음)는
가서 봐야 안다 — **숫자가 좋아 보이는 것 자체가 신호**이기 때문이다.

실측이 이 구조를 뒷받침한다(`불일치탐지.md` §4):
검사 강화 권고는 실제로 나쁜 오더를 74.7% 잡고(기저 18.5%),
현장 방문 권고는 편향이 심한 공장을 95.6% 잡는다(기저 51.3%).

신뢰도 하위 25% 공장은 **점선 테두리 + 라벨**로 표시한다. 색만으로 구분하지 않는다.

## 3. 현장 화면

### 「지금 개선할 수 있는 것」이 이 화면의 목적

| 항목 | 왜 |
| --- | --- |
| 초도품 검사(FAI) 제출 | 오더 초반에 위험을 볼 수 있는 유일한 자료 |
| 주간 보고 누락 | 보고가 없으면 평가가 과거 실적만으로 내려간다 |
| 보고 지연 | 예정일 대비 |
| 자체 검사 결과 기입 | 검사 수량과 불합격 수를 함께 받아야 추정이 정확해진다 |

문구를 **요구가 아니라 설명**으로 쓴다. "제출하세요"가 아니라
"오더 초반에 위험을 볼 수 있는 유일한 자료입니다".

## 4. 표시 규칙

- **PPM 단위로 낸다.** 구매·품질 담당자가 쓰는 문법이라 설명이 필요 없다
- **미보고는 "미보고"라고 쓴다.** 0%가 아니다 — 결측과 무결함은 다르다
- 상태색은 4단계 고정(`good`/`warning`/`serious`/`critical`)이고 **항상 라벨과 함께** 쓴다
- 위험 등급은 계약의 4-tier(`low`/`medium`/`high`/`critical`)를 그대로 쓴다

## 5. 남은 것

1. **`sr serve`** — 지금은 정적 발행본이다. 실제 운영은 서비스가 필요하다
2. **멀티테넌트 격리** — 현장 화면이 자기 공장만 보는 것을 **화면이 아니라 서버에서** 막아야 한다.
   지금은 같은 페이지에서 필터링할 뿐이다
3. **불일치 사유 분해** — 지금은 스칼라 하나다. 교차검증 쌍 중 어느 짝이 어긋났는지를 내면
   "왜"를 한 줄로 보여줄 수 있다
4. 갱신 주기 — 공장 보고가 주 1회면 실시간으로 돌려도 값이 안 바뀐다(CTO 질문 17번)
