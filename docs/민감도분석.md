## 1. 2단 모델 — 왜 필요했나

1단 모델은 escape 를 직접 맞힌다. 그런데 오더 하나에서 우리가 보는 것은
**표본 88개 중 불량 0.11개**다. 900 오더를 다 모아도 학습 신호가 거의 없다.

반면 공장 자체검사는 전수에 가깝다 — 내부 불량 3% × 1,162개 생산 = **34개**.
**사건 수가 수백 배**(8 seed 중앙 319배)인데, 1단 모델은 그걸 피처로만 썼다. 피처는 y 를 설명하는 데만 쓰이고
y 는 여전히 0.11개짜리 희소 관측이라, 그 수백 배가 하나도 안 쓰였다.

대수적으로 쪼개면 길이 보인다.

```
escape = internal × (1 − detection)          ← 우리가 원하는 값
보고   = internal × bias                     ← 전수에 가깝다
──────────────────────────────────────────────
escape = 보고 × (1 − detection) / bias
                └──── κ (공장별 상수) ────┘
```

**`detection` 과 `bias` 를 따로 알 필요가 없다. 둘의 비 κ 만 알면 된다.**
그리고 κ 는 공장당 스칼라 하나라 희소한 라벨로도 추정이 선다.

| 단계 | 하는 일 | 쓰는 신호 |
| --- | --- | --- |
| **1단계** | 보고 카운트를 L0 사전분포 쪽으로 shrink → `internal_hat` | 정보량 큰 쪽. **순위**를 잡는다 |
| **2단계** | 공장별 κ 를 Gamma-Poisson conjugate prior 로 추정 | 희소한 우리 라벨. **눈금**만 맞춘다 |

`k ~ Poisson(n × internal_hat × κ)` 이고 Gamma 가 conjugate prior 라 사후분포가 닫힌 형태다 —
`Gamma(a + Σk, b + Σ n·internal_hat)`. 표본 200개에서 0건과 50개에서 0건이 자동으로 다르게 반영된다.
이력 없는 공장은 전체 평균 κ 쪽으로 당겨진다(partial pooling).

**두 단계 모두 시간을 지킨다.** κ 는 그 오더를 발주하던 시점까지 **도착한** 라벨만으로
갱신한다. 유럽 오더는 라벨이 두 달 뒤에 오므로, 이걸 어기면 현실에서 불가능한 추정이 된다.
`tests/unit/test_two_stage.py::test_kappa_uses_only_arrived_labels` 가 이 성질을 고정한다.

### 성능

| 모델 | 계층 | Spearman 상관 | binomial log loss |
| --- | --- | --- | --- |
| 1단 | L0 | +0.359 | 0.00808 |
| 1단 | L0+L0′ | +0.446 | 0.00797 |
| 1단 | L0+L0′+L1 | +0.508 | 0.00802 |
| **2단** | **L0+L0′+L1** | **+0.759** | **0.00767** |

누수가 아니다 — 관측 y 와의 최대 피처 상관은 **0.300** 으로 게이트(0.40) 안이다.
높은 성능은 `보고 → internal → escape` 라는 **인과 사슬**에서 나온다.

## 2. ⚠ 이 분석이 생성기의 결함을 하나 더 찾았다

처음 2단 모델을 돌렸을 때 Spearman 상관이 **0.827** 이었다. 너무 좋았다.

원인은 생성기에 **보고 노이즈가 없었다**는 것이다. 편향(평균이 어긋남)만 넣고

`report_noise_cv` 를 넣고 다시 재니 **0.759** 다. 이쪽이 정직한 숫자다.

## 5. 읽은 것

### ★ (1) 두 기능이 전 구간에서 서로를 덮는다

보고가 나빠질수록 **예측 기여는 떨어지고 불일치 탐지는 올라간다.** 두 축에서 같은 패턴이 나온다.

| | 계층 증분 | gap 복원 |
| --- | --- | --- |
| 보고 노이즈 없음 (cv 0.0) | **+0.383** | +0.521 |
| 보고 노이즈 극심 (cv 1.5) | +0.106 | **+0.782** |
| 편향 심함 (bias 0.3) | +0.313 | **+0.548** |
| 편향 약함 (bias 0.9) | **+0.402** | +0.428 |
| 나쁠수록 더 숨김 (sens 1.0) | +0.297 | **+0.527** |

**정직한 공장에서는 보고가 예측에 기여하고, 부정직하거나 엉성한 공장에서는 불일치 탐지가
기여한다.** 어느 쪽 공장이든 하나는 작동한다. 제품 서사에 그대로 쓸 수 있다.

### ★ (2) 보고 품질은 우리가 통제할 수 있는 변수다

`report_noise_cv` 가 2단 모델 성능을 가장 크게 움직인다(0.829 → 0.551).
그런데 **이 값은 자연 상수가 아니라 협상과 양식 설계의 결과다** —
불량 유형 표준코드를 내려보내고, 검사 수량을 함께 받고, 양식을 고정하면 노이즈가 줄어든다.

→ 수집명세의 T2 요구 항목이 왜 그렇게 구체적이어야 하는지가 여기서 정량화된다.

### (3) 공장이 표류할수록 보고가 더 중요해진다

`within_factory_ar1` 을 0 → 0.85 로 올리면 L0 가 **+0.488 → +0.313** 으로 떨어지고
증분은 **+0.342 → +0.448** 로 커진다. 과거 실적이 무너지는 만큼 현재 보고가 메운다.

→ CTO 질문 21번(작년에 좋던 공장이 올해도 좋습니까)의 답이
**"출렁인다"면 L1 요구가 더 정당해진다.**

### (4) 공장 간 격차가 크면 L0만으로 충분해진다

`factory_capability_sd` 0.5 → 2.0 에서 L0 가 +0.41 → +0.51.
**"협력사들이 다 고만고만하다"는 상황일수록 보고를 받아야 한다.**

### (5) 가장 걱정했던 가정이 가장 무해했다

`severity_critical` 은 불합격률만 움직이고(0.4% → 3.4%) 순위 결론은 거의 안 바꾼다.
게이트를 통과시키기 위해 필요한 값이지 결론을 만드는 값이 아니다.

### ⚠ (6) 시드 편차가 인접 수준 차이보다 크다

L0 성능의 시드 표준편차가 **±0.03~0.15** 다. "이 값이 저 값보다 낫다"는 3 seed 로
단정할 수 없다. 말할 수 있는 것은 방향과 범위, 그리고 **부호가 뒤집히지 않는다**는 것뿐이다.
최종 보고용 숫자는 seed 를 5~10개로 늘려야 한다.

## 6. 남은 것

1. **seed 5~10개로 재측정** — 지금 3 seed 로는 인접 수준을 구분 못 한다
2. **κ 의 시간 가중** — §5(3)에 따라 오래된 라벨의 비중을 낮춘다
3. **불일치 탐지를 독립 산출물로** — 지금은 평가 지표일 뿐 모델이 아니다.
   `예측 품질 · 보고 품질 · 불일치도` 세 값을 내는 출력 계약이 필요하다
4. L2(텔레메트리)가 붙었을 때의 증분 — 설치 공장이 생기면
