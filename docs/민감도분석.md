# 민감도 분석 — 결론이 가정에 얼마나 의존하는가

실행 2026-09-07. `scripts/sensitivity.py`. **20개 조건 × 3 seed = 60 실행.**

생성기 파라미터 다섯 개는 실측 근거가 없다(`생성기_캘리브레이션.md` §2.3~2.4).
그 값을 흔들었을 때 결론이 따라 흔들리면, 그건 데이터에서 나온 결론이 아니라
**우리가 넣어 둔 가정을 되읽은 것**이다.

---

## 0. 결론 두 줄

| 주장 | 강건한가 |
| --- | --- |
| **보고-실제 격차를 관측값에서 복원할 수 있다** (핵심 상품) | **20/20 조건에서 모든 개별 실행이 양수.** 최악의 실행 **+0.222** |
| **L1을 받으면 예측이 좋아진다** (계층 증분) | ⚠ **15/20 조건에서만** 모든 실행이 양수. 최악의 실행 **−0.046** |

**핵심 상품은 가정에 의존하지 않는다. 계층 증분 주장은 아직 단정할 수 없다.**

---

## 1. 잰 것

| 지표 | 의미 |
| --- | --- |
| `L0` | 거래 이력만으로 어디까지 되나 (예측 위험도 ↔ **진짜** escape rate 순위상관) |
| `L0+L0′+L1` | 공장 보고까지 받으면 |
| `증분` | 둘의 차 — **계층 증분이 이 프로젝트의 영업 주장이다** |
| `gap 복원` | 관측값만으로 보고-실제 격차를 복원한 순위상관 — **핵심 상품** |
| `불합격률` | 생성 데이터가 여전히 실무 범위(1~10%)에 있나 |

주 지표를 이진 분류로 두지 않은 이유: 900 오더 중 로트 불합격이 20여 건이고
시간순 테스트 구간에는 **7건**만 남는다. 신뢰구간이 결론보다 넓다.
`true_escape_rate` 순위상관은 합성 데이터에서만 잴 수 있고, `ground_truth.jsonl` 을
따로 만들어 둔 이유가 이것이다.

## 3. 읽은 것

### ⚠ (1) 시드 편차가 인접 수준 차이보다 크다

L0 성능의 시드 표준편차가 **±0.07~0.15** 다. 즉 `capability_sd` 0.5(+0.406)와
1.0(+0.359)의 차이는 **노이즈 안에 있다.** 말할 수 있는 것은 방향과 범위뿐이고,
"이 값이 저 값보다 낫다"는 3 seed 로 단정할 수 없다.

> 기존 프로젝트에서 1 seed 결론이 3 seed 재측정에 뒤집힌 전례가 있다.
> 최종 보고용 숫자는 seed 를 더 늘려야 한다.

### (2) 공장 간 격차가 클수록 L0만으로 충분해진다

`factory_capability_sd` 0.5 → 2.0 에서 L0 가 **+0.41 → +0.51**, 증분은 **+0.101 → +0.091**.

공장들이 확연히 다르면 과거 실적만으로 갈리고, 비슷비슷하면 보고를 받아야 한다.
**영업 논리가 뒤집히는 지점이다** — "협력사들이 다 고만고만하다"는 고객일수록
L1 요구가 정당하다.

### ★ (3) 정직한 공장과 부정직한 공장이 서로 다른 상품을 필요로 한다

`report_bias_mean` 을 흔들면 두 지표가 **반대로** 움직인다.

| 편향 | 계층 증분 | gap 복원 |
| --- | --- | --- |
| 심함 (0.3) | +0.142 | **+0.548** |
| 약함 (0.9) | **+0.183** | +0.428 |

정직한 공장에서는 보고가 예측에 기여하고, 부정직한 공장에서는 불일치 탐지가 기여한다.
**두 기능이 서로를 보완한다** — 어느 쪽 공장이든 하나는 작동한다.
제품 서사에 그대로 쓸 수 있는 결과다.

### (4) 핵심 상품의 전제는 필요조건이 아니었다

`bias_sensitivity`(나쁠수록 더 숨김) 0 → 1 에서 gap 복원이 **+0.389 → +0.527** 로
단조 증가한다. 가정대로 작동한다.

그런데 **0(전혀 더 숨기지 않음)에서도 +0.389** 다. 즉 불일치 탐지는
"나쁠수록 더 숨긴다"는 가정에 **전적으로 의존하지 않는다.** 가장 걱정했던 가정이었는데
없어도 절반 이상 남는다.

### ★ (5) 예상 못한 것 — 공장이 변하면 과거 실적이 무너진다

`within_factory_ar1` 0 → 0.85 에서 L0 가 **+0.440 → +0.282** 로 **떨어진다.**

직관과 반대로 보이지만 맞다. ρ가 높으면 공장 상태의 저주파 성분이 커져서
학습 기간의 상태와 테스트 기간의 상태가 달라진다. **1년 전 실적으로 지금을 판단하는
것이 통하지 않는다는 뜻이다.**

→ 실무 함의: 이력 피처에 **최근 가중**을 넣어야 한다. 그리고 CTO 질문에 하나 추가 —
**"공장 품질이 시간에 따라 얼마나 변합니까? 작년에 좋던 곳이 올해도 좋습니까?"**

### (6) 가장 걱정했던 가정이 가장 무해했다

`severity_critical` 은 **불합격률만** 움직인다(0.4% → 3.4%). L0 와 증분은 거의 불변.

즉 이 가정은 **게이트를 통과시키기 위해 필요한 값**이지 결론을 만드는 값이 아니다.
다만 critical 0.05 면 불합격률 0.4% 로 실무 범위(1~10%) 하한을 벗어난다 —
**로트 불합격률을 실무 범위로 만드는 것은 major AQL 이 아니라 critical 비중**이라는
구현 중 발견이 여기서 다시 확인된다.

## 4. ⚠ 이 분석이 드러낸 설계 결함

**계층 증분이 약한 이유를 알 것 같다. L1을 잘못 쓰고 있다.**

`생성기_캘리브레이션.md` §1(2)에서 이렇게 계산했었다.

| | 오더 1건당 기대 불량 관측 |
| --- | --- |
| 우리 입고검사 (escape 0.1% × 표본 200) | **0.2개** |
| 공장 내부검사 (3% × 전수 1,000개) | **30개** |

**100배 차이다.** 그런데 지금 베이스라인은 공장 자체검사 결과를 **피처로만** 쓴다.
피처는 y 를 설명하는 데만 쓰이고, y 는 여전히 0.2개짜리 희소 관측이다.
**100배의 정보량이 하나도 쓰이지 않고 있다.**

→ **다음 할 일: L1 자체검사 결과를 보조 타깃으로 쓰는 다중 타깃 구조.**
   `internal_defect_rate` 를 먼저 추정하고, `detection_rate` 를 공장별로 추정해
   escape 로 내리는 2단 모델. 이게 §0 표의 두 번째 줄을 뒤집을 후보다.

---

## 5. 남은 것

1. **seed 를 5~10개로 늘려 재측정.** 지금 3 seed 로는 인접 수준을 구분 못 한다
2. **2단 모델**(내부 불량률 → detection → escape)로 계층 증분 재측정
3. **이력 피처에 최근 가중** — §3(5)
4. CTO 질문 추가 — 공장 품질의 시간 안정성
