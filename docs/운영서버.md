# 운영 서버 — `sr serve` (2026-09-08 저녁, 1차)

정적 발행본(아티팩트)은 설계 검증용이었다. 운영물은 데이터가 **들어오고 · 저장되고 · 매일 채점되고 · 권한이 갈려야** 한다.

```
FactoryOS(MES·CellOS·ERP 수집) ─POST /api/ingest/{계약}─▶ SQLite (계약 행 원본 JSON + 조회 키)   ← erp-daily.v1 추가(09-08 저녁)
우리 검사·클레임         ─POST /api/ingest/order-quality-outcome.v1─▶      │
                                                                       ▼
                                        sr score-run (cron 일 1회) 또는 POST /api/score/run
                                        계약 행 → ingestion.derive → build() → 혼합 C 채점 → score_runs
                                                                       │
브라우저 ◀── GET /  (관제 화면, __LIVE__) ◀── GET /api/dashboard ◀── X-API-Key ─┘
```

## 결정과 이유

| 결정 | 이유 |
| --- | --- |
| 계약 JSON 을 API 로 받는다 | 오늘 만든 계약 6종이 그대로 입력 규격. 생성기 출력도 같은 경로로 넣어 테스트한다(`sr seed`) |
| SQLite 한 파일 + SQLAlchemy Core | 공장 12곳 · 오더 수천 건. 원본 JSON 을 `payload` 로 보관하고 키만 열로 — 스키마가 바뀌어도 원본이 남는다. Postgres 로 옮길 때 URL 만 바꾼다 |
| 파생은 서버가 다시 계산한다 | `lead_slack`·`price_zscore`·L0′ 메타는 생성기가 만들던 값. `ingestion/derive.py` 가 계약 행에서 같은 식으로 만든다. **왕복 테스트**가 생성기 직행과 같은 피처를 보장한다(`test_derive.py`) |
| 정답값 없음 · 결과 없음을 견딘다 | `build()` 는 truth 가 없으면 NaN, 결과가 아직 없는 오더는 y NaN. 2단 모델의 κ 온라인 갱신은 라벨 없는 행을 건너뛴다 |
| 시간 규율 | 학습 = `label_available_at ≤ 지금` 인 오더만. 채점 = 발주된 오더 전부. 화면의 "완료"도 **결과를 우리가 알게 된** 오더다 — 결과 행이 있어도 라벨 시각이 뒤면 진행 중 |
| API key 세 역할 | `admin` 전 공장·채점·키 발급 / `site` 자기 공장 하나(**서버에서** factory_id 로 자름) / `ingest` 쓰기만. 키는 해시만 저장 |
| 화면은 그대로, 데이터만 fetch | 템플릿의 데이터 자리가 `__DATA__` 면 정적, `__LIVE__` 면 `/api/dashboard`. 키는 `?key=` 로 한 번 받아 localStorage. 현장 계정은 관리자 탭이 숨겨진다 |
| 배치 전체 거절 | ingest 에서 한 행이라도 스키마 위반이면 422 — 반쯤 들어간 배치는 재전송을 어렵게 만든다 |

## 쓰는 법

```
sr seed --score                 # 생성 데이터를 계약 경로로 넣고 admin 키 발급 + 채점 1회 (데모)
sr serve --port 8020            # 서버. 브라우저: http://localhost:8020/?key=<키>
sr key --role site --factory fac_kr_01 --label "공장01 현장"
sr score-run                    # cron 용. MES 가 일 1회라 일 배치로 충분하다
SR_DATABASE_URL=sqlite:///data/supplier_risk.db   # 기본. 다른 DB 는 URL 로
```

## 남은 것 (2차)

- FactoryOS SSO / 사용자 계정 — 지금은 발급 키
- 키 폐기·회전 명령 (`revoked` 열은 있다)
- 결과 도착 시 자동 재채점 (지금은 일 배치)
- 채점 이력 비교 화면 (run 간 변화)
- 운영 지표: 실데이터에는 진실이 없으므로 binomial log loss 와 로트 불합격 예측력으로 본다(`evaluation/metrics.py`)
